# AegisOps on AWS (single EC2, ap-south-1)

Cheapest setup that runs the full stack: one Graviton instance running the same Docker Compose stack as local, behind nginx with a free Let's Encrypt certificate. No load balancer, NAT gateway, RDS or CloudWatch log groups.

`13-127-211-52.sslip.io` is a free public DNS name that always resolves to `13.127.211.52`. Let's Encrypt does not issue normal certificates for bare IP addresses, so this is what makes real HTTPS possible without buying a domain. When you get a domain, point it at the Elastic IP and set `DOMAIN` (see "Use your own domain").

## Security

| Layer | Setting |
|---|---|
| Port 443 | allowed only from `allowed_cidrs` (your network's 4 egress IPs) |
| Port 80 | open to the internet because Let's Encrypt must reach it; serves only the ACME challenge and a redirect to HTTPS, never the app |
| Ports 8000/3000/9000/9090/9093 | bound to `127.0.0.1` on the instance; not reachable from the internet |
| SSH | no port 22 rule and no key pair; shell access through SSM only |
| TLS | TLS 1.2/1.3, HSTS, `X-Frame-Options: DENY`, `nosniff`, `no-referrer`, `server_tokens off` |
| Login | nginx rate limit on `/api/auth/token` (10/min per IP, burst 5) plus the app's own limits |
| Secrets | generated by Terraform into SSM Parameter Store (SecureString); rendered to a root-only `.env` on the instance |
| Instance | IMDSv2 only, encrypted disk, IAM role can only read `/aegisops/*` parameters and the bundle object |

## Gemini key (configured)

Gemini is live: the key is the SecureString `/aegisops/GEMINI_API_KEY` (KMS `alias/aws/ssm`), the model is `gemini-3.5-flash-lite`, and `/api/v1/system/health` reports `"llm_mode": "llm"`. It is never written into the repository or the image; `render_env.sh` copies it into the root-only `.env` on each redeploy.

* Each CrewAI run is capped at `AEGIS_LLM_TIMEOUT_SECONDS` (default 45) with at most 3 iterations and 1 retry per specialist. On timeout or any API error the specialist falls back to the deterministic analyzer (`reasoning_mode: deterministic`) and the postmortem records `crewai_error`.
* `REDIS_URL` is deliberately empty for the `aegisops` container: if it is set, CrewAI's lock store tries to reach Redis and every LLM call fails.

To rotate or replace the key:

1. Store it (use `aws ssm put-parameter --overwrite` from your own terminal so the key never passes through chat):
   ```bash
   aws ssm put-parameter --region ap-south-1 --name /aegisops/GEMINI_API_KEY --type SecureString --overwrite --value "<your-key>"
   ```
2. Ship it to the running app:
   ```bash
   bash infra/aws/redeploy.sh
   ```
   `render_env.sh` re-reads every `/aegisops/*` parameter on each redeploy, so the reasoning mode switches to LLM. Check it at `/api/v1/system/health` (`"llm_mode": "llm"`).

## Cost

Your account is on the AWS **Free plan** (credit-based): all usage is paid from your **$137.89 credits** (they expire 2027-02-27), not from your card. On this plan there is no free 750-hour allowance; eligible instance types (including `t4g.small`) simply draw credits.

| Resource | Monthly cost |
|---|---|
| EC2 `t4g.small` (2 GiB Graviton, Free-plan eligible) | $8.18 ($0.0112/h) |
| 20 GB gp3 root volume (encrypted) | $1.82 ($0.0912/GB) |
| Elastic IP (attached) | $3.65 ($0.005/h; same price as an auto-assigned public IPv4) |
| Private S3 bundle (1.9 MB), 4 SSM standard parameters, IAM, security group | < $0.01 |
| AWS Budget `aegisops-monthly` ($10, alerts 50/75/90/100%) | $0 (first 2 budgets free) |
| Let's Encrypt certificate, sslip.io hostname | $0 |
| **Total** | **≈ $13.65 / month** |

From now until the plan ends (about 3.5 months) that is roughly **$48 of your $137.89 credits**, so the deployment runs at no out-of-pocket cost for the whole Free plan. Prices are Mumbai on-demand Linux rates from AWS's public price list (Nov 2026); data out is free up to 100 GB/month. Budgets alert only; they do not stop resources.

**Cost decisions**

| Choice | Why |
|---|---|
| `t4g.small`, not `t3.small` ($21.80/mo) or `t3a.small` | cheapest 2 GiB type allowed on the Free plan; measured peak needs ~1.2 GiB, so 1 GiB types (`t3.micro`, `t4g.micro`) would hit the OOM killer |
| No ALB (~$18/mo), NAT (~$35/mo), RDS, CloudWatch logs | nginx on the instance does TLS; the app keeps state on the EBS disk; Docker logs rotate locally |
| 20 GB disk kept | 6.6 GB used; EBS cannot shrink in place, and replacing the instance to save ~$0.70/mo is not worth the risk. `redeploy.sh` prunes old images |
| Elastic IP | cost-neutral versus the auto-assigned IP while running; keeps the HTTPS hostname and webhook URL fixed |
| Stop when idle (optional) | saves compute only (~$0.27/day); the Elastic IP is still billed while stopped |

When the Free plan ends you must upgrade the account to keep resources running; review this table then.

## Operate

Prerequisite for every command: `aws login` (the CLI session expires). Terraform needs the temporary credentials exported:

```bash
eval "$(aws configure export-credentials --format env)"
```

Ship code changes or new SSM secrets (rebuilds on the instance, keeps data volumes):

```bash
bash infra/aws/redeploy.sh
```

Run the 9-scenario self-check on AWS (inside an SSM shell):

```bash
cd /opt/aegisops/app && sudo docker compose -f docker-compose.yml -f docker-compose.aws.yml run --rm selfcheck
```

Restart the stack (SSM shell):

```bash
cd /opt/aegisops/app && sudo docker compose -f docker-compose.yml -f docker-compose.aws.yml restart
```

Allow another IP (e.g. your website's egress IP): add it to `allowed_cidrs` in `terraform.tfvars`, then:

```bash
cd infra/aws/terraform && terraform apply
```

Do not edit the security group's `description`: AWS treats that as a replacement, and a group attached to a running instance cannot be deleted.

Stop / start the instance (compute billing pauses; data, Elastic IP and hostname stay):

```bash
aws ec2 stop-instances --region ap-south-1 --instance-ids $(terraform -chdir=infra/aws/terraform output -raw instance_id)
```

```bash
aws ec2 start-instances --region ap-south-1 --instance-ids $(terraform -chdir=infra/aws/terraform output -raw instance_id)
```

Remove everything this Terraform created (irreversible: deletes the instance, its disk, incident history and the Elastic IP):

```bash
cd infra/aws/terraform && terraform destroy
```

## Use your own domain

Create an A record pointing your domain at the Elastic IP, then on the instance (SSM shell) set `DOMAIN=your.domain` in `/opt/aegisops/app/.env` and restart nginx and certbot. To make it permanent, change the `DOMAIN=` line in `infra/aws/render_env.sh`.

## Reboot and persistence

Docker is a systemd service and every container uses `restart: unless-stopped`, so the stack (including nginx and certbot) comes back after a reboot. Incident state and the audit log live in the `aegis-data` Docker volume; certificates live in the `letsencrypt` volume. Boot log: `/var/log/aegisops-bootstrap.log`.

## Terraform state

State is local (`infra/aws/terraform/terraform.tfstate`, git-ignored). It contains the generated secrets, so keep it private and backed up. Move it to an encrypted, private S3 backend if more than one person will manage the deployment.

## ShopFront on the same instance

ShopFront (`shopfront/`) runs as a separate Compose project (`-p shopfront`) on the shared `aegis-net` network and is started by `redeploy.sh`. Store: **https://shop.13-127-211-52.sslip.io/** (same allowed IPs as the console; the certificate covers both names). It adds no AWS resources and about 200 MiB of memory at rest; both stacks together use ~1.0 GiB of the 1.8 GiB instance. Its secrets (`SHOPFRONT_DB_PASSWORD`, `SHOPFRONT_FAULT_TOKEN`, ops token `AEGIS_HOOK_TOKEN_SHOPFRONT`) are SSM parameters like the others.

Run the six ShopFront scenarios on AWS (SSM shell):

```bash
cd /opt/aegisops/app && sudo docker compose -f docker-compose.yml -f docker-compose.aws.yml run --rm shopfront-check
```

Inject a single fault by hand (see `shopfront/README.md` for all six and their rollbacks):

```bash
sudo docker exec shopfront-shopfront-api-1 python -m shopfront.faultctl inject db
```
